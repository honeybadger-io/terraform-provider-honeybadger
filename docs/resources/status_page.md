# honeybadger_status_page (Resource)

A public status page. Readable and deletable after the plan loses status pages; creating and editing need the feature.

## Example Usage

```terraform
resource "honeybadger_status_page" "public" {
  name = "Example status"

  sites = [
    { site_id = honeybadger_site.api.id, display_name = "API" },
  ]

  check_ins = [
    { check_in_id = honeybadger_check_in.nightly.id, display_name = "Nightly billing" },
  ]
}

# The page's public address, to link from your site or docs.
output "status_page_url" {
  value = honeybadger_status_page.public.url
}

# Where to edit the page in Honeybadger.
output "status_page_admin_url" {
  value = honeybadger_status_page.public.links.web
}
```

## Notes

- **`password`** is write-only: Honeybadger never returns it, so Terraform keeps the value it last sent, and a password changed in Honeybadger isn't detected.
- **Plan features:** `features`, `password_protected`, `username` and `password` need advanced status pages, and `incidents_enabled` needs status page incidents; otherwise the API refuses a change with a 403.
- **`incidents_enabled`**, left out, is set by Honeybadger from whether the plan has incidents, and state shows it.
- **`domain`** is unique across Honeybadger, and an account can change at most 30 domains a week.
- **`sites` and `check_ins`** are in page order.
