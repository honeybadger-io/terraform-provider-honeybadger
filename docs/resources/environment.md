# honeybadger_environment (Resource)

An environment a project's errors are reported from, such as production or staging, and whether errors from it send notifications. Required scopes: `projects:read`, `projects:write`.

## Example Usage

```terraform
resource "honeybadger_environment" "staging" {
  project_id    = honeybadger_project.app.id
  name          = "staging"
  notifications = false
}
```

## Schema

### Required

- `name` (String) Environment name
- `project_id` (String) The project's `id`, as a project read returns it.

### Optional

- `notifications` (Boolean) Whether errors in this environment notify. Null means the default. Defaults to `true`.

### Read-Only

- `created_at` (String) When the environment was created
- `id` (String) Unique identifier

## Import

Import is supported using the following syntax:

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = honeybadger_environment.staging
  id = "<project_id>/<id>"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
terraform import honeybadger_environment.staging "<project_id>/<id>"
```

## Notes

- **Existing environments:** Honeybadger creates an environment the first time an error arrives from it, so the one you want to manage often exists already, and creating it again fails with a 422. Adopt it with an `import` block instead, using the project ID and the environment's ID:

  ```terraform
  import {
    to = honeybadger_environment.production
    id = "<project_id>/<environment_id>"
  }
  ```

- **Renaming** replaces the environment: the API can't rename one.
